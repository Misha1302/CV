.NET backend · payments · subscriptions · recovery

VpnMediator / Razaltush VPN · independently maintained service

Maintain the ASP.NET Core subscription, access, and device backend in a system with a Python Telegram bot and SQLite. The code implements idempotent processing of duplicate payment events, state reconciliation, operation recovery, and coordinated backups with deployment rollback.

Full case study ↗

Problem

Payment, subscription, and actual access can diverge after duplicate webhooks, timeouts, or process restarts.

Approach

Explicit access and payment states, idempotent operations, audit trails, background reconciliation, migrations, and verifiable recovery paths.

Outcome & limits

Verifiable state transitions, backup/restore, health gates, and rollback-aware deployment; the public case study excludes secrets and user data.

.NET · modular language/toolchain infrastructure · runtime architecture

UniversalToolchain · open-source C#/.NET project

Developing modular language infrastructure: a typed LanguagePlan validates dependencies before execution, while interpreter and CIL backends are checked for agreement between execution results.

Full case study ↗ Source code ↗

Problem

Frontend, semantic components, IR/optimization passes, and execution backends should evolve independently while composing into one deterministic toolchain without hidden registration-order dependencies.

Approach

Typed contracts/capabilities, dependency/conflict resolution, deterministic contribution ordering, and typed artifact routes are resolved into one LanguagePlan before runtime materialization.

Outcome & limits

Implemented an end-to-end pipeline with frontend, IR, optimization passes, interpreter, and a CIL backend; current exact test manifest: 1,324/1,324.
