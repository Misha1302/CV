# CV upgrade — what changed and why (2026-11-23)

## Правила, по которым правился текст

1. **Ни одного самоподрыва.** Формулировки «по данным автора», «сообщено кандидатом», «в разработке» внутри основного текста резюме убраны. Ограничения доказательств живут в отдельном разделе (`releases/*/04_Public_Evidence_Boundaries.md`), а не в теле CV.
2. **Число — только воспроизводимое.** В публичном тексте остаётся то, что можно пересчитать по репозиторию (120+ активных учеников, 514 тестов, 1324 теста, 29/29, 18/18). Данные владельца продукта («150+») не используются.
3. **Ничего, что позволяет посчитать курс.** Из траектории, proof-блоков и достижений удалены годы до 2020-х, кроме рабочего 2026. Олимпиады сохранены и усилены, но без годов.
4. **Опыт = оплаченная работа.** В «Профессиональный опыт» остаётся только то, за что платили: ИСП РАН, МЦСТ, клиентские проекты (KeyAuth, Diploma.school). Агентные LLM-пайплайны остаются в опыте по решению владельца — они оплачивают разработку TuringSquare.
5. **Один факт — одно место хранения.** Тексты правятся в `data/site.json` и `knowledge/resume-evidence.json`; HTML/PDF только пересобираются.
6. **Каждый claim имеет asset.** У каждого блока опыта есть `fact_ref` в `experience_facts`; у каждого проекта — `evidence_refs` в `knowledge/resume-evidence.json`.
7. **Один PDF — одна страница A4.** Сборка падает, если страниц больше одной; минимальный кегль в PDF ≥ 7 pt.

## Бенчмарки, на которые опирается дизайн

- Первичный скан резюме — 7.4 c (Ladders, 2018). Верхние ~⅓ первой страницы решают, читают ли дальше.
- Tailoring под вакансию: 10.6× interview rate против generic; cover letter 3.4× (Jobscan 2025, 2.5 млн откликов).
- Tailored cover letter: +53% callback (ResumeGo RCT, 7 287 откликов).
- ATS-автореджект — миф: 23 из 25 систем не отклоняют автоматически (Enhancv 2025). Значит, оптимизировать надо под человека, а не под парсер.
- Junior C# РФ (16 вакансий): .NET 13/16, SQL 10/16, Git 9/16, MS SQL 6/16, EF Core 5/16, Docker/K8s/CI 0/16 — поэтому Docker/CI не выпячиваются, а .NET/SQL стоят первыми.

## Как проверялось

- `tools/validate_cv.py` — PASS (20 профилей, 59 страниц, 20 PDF).
- `tools/validate_release.py` — PASS (22 записи в zip, 36 evidence assets).
- `tools/validate_resume_knowledge.py` — `status: ok`, 36 assets.
- Все 20 PDF: 1 страница, кегль ≥ 7 pt, нет годов кроме 2026.
- Негативный контроль: строка «Студент 1 курса, 17 лет» → валидатор падает на age-privacy; подставленные годы «2019 — 2020» → видны в PDF, то есть проверка на годы работает как внешний контроль, а не как самоотчёт.
