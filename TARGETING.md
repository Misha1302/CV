# Targeting guide — role-specific CV suite

## Primary profiles

1. `Compiler & Program Analysis Engineer — LLVM · C++ · Static Analysis` — default for compiler, LLVM, static/program-analysis, compiler-backend, and adjacent code-intelligence roles.
2. `Compiler Infrastructure / Language Tooling Engineer` — language infrastructure, compiler platforms, extensible DSL/language tooling, deterministic composition, and runtime/toolchain roles.
3. `Software Engineer — Architecture & Platforms` — hands-on architecture/platform roles where ownership boundaries, contracts, state/recovery, lifecycle decisions, and mechanically checked invariants matter. This is intentionally not titled `Software Architect`: multi-team/enterprise architecture authority is not claimed.
4. `.NET Backend / Platform Engineer — State & Reliability` — backend/platform roles where payments, idempotency, recovery, migrations, and release correctness dominate.

## Secondary profiles

- `Compiler Backend / Code Generation Engineer` — LLVM/backend, native codegen, register allocation, and low-level compiler roles.
- `Static Analysis / Program Analysis Engineer` — Roslyn/LLVM data-flow and conservative program-analysis roles.
- `C++ / LLVM Systems` — systems, performance, low-level infrastructure, and HFT-adjacent applications.
- `Quant Developer / Research Engineer` and `Quant Research Candidate` — selective roles where algorithmic experimentation and reproducible validation are central.
- `Compiler / Software Protection Engineer` — selective / evidence-limited; use only for directly relevant roles.

## Architecture profile evidence order

`UniversalToolchain -> VpnMediator -> x86-64 backend`. The profile proves architecture through implemented ownership boundaries, state/recovery semantics, and independent verification rather than through design-pattern vocabulary or an inflated seniority title.

All profiles share canonical facts from `data/site.json`; they differ only in evidence ordering and role-specific vocabulary.
