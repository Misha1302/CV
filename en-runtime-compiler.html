.NET · modular language/toolchain infrastructure · runtime architecture

UniversalToolchain · C#/.NET compiler/runtime infrastructure

Developing modular language infrastructure with Bytecode/AIR and interpreter/CIL execution paths. A typed LanguagePlan validates module composition and dependencies before runtime; tests compare results between backends.

Problem

Frontend, semantic components, IR/optimization passes, and execution backends should evolve independently while composing into one deterministic toolchain without hidden registration-order dependencies.

Approach

Typed contracts/capabilities, dependency/conflict resolution, deterministic contribution ordering, and typed artifact routes are resolved into one LanguagePlan before runtime materialization.

C++23 · LLVM 22 · interprocedural analysis · optimization

LLVM Global IV · interprocedural optimization

An experimental LLVM 22 pass promotes selected integer-global accesses inside loops. Effect analysis and PromotionLegality precede IR transformation. Passed 29/29 regression cases on LLVM 22.1.8, including supported and rejected transformations.

Full case study ↗ Source code ↗

Problem

The pass must recognize affine evolution of global IVs across calls and transform IR only when correctness conditions are established.

Approach

APInt affine b + k·x evolution, transitive function/module effects, loop/dominator/must-execute reasoning, and a separate conservative legality phase that rejects unsupported CFG/calls.

Outcome & limits

A conservative LLVM 22 prototype/MVP with an actual IR transform; 29 positive/negative regression cases cover verifier validity, idempotence, and before/after execution.

C# · Roslyn · static analysis · data-flow

DerefAfterNullAnalyzer · Roslyn CFG / data-flow

Built fixed-point null-state propagation across branches, loops and state joins. Passed 18/18 tests on a pinned Git revision. This is a separate project, not a claimed SharpChecker integration.

Full case study ↗ Source code ↗

Problem

The analyzer must detect potentially unsafe dereferences after a possible null while accounting for branches, loops, and control-flow joins.

Approach

Roslyn ControlFlowGraph with forward fixed-point data-flow analysis: Unknown/MaybeNull/NotNull states propagate across basic blocks and merge at join points.

Outcome & limits

Diagnostics for potentially unsafe dereference paths over the real CFG, with successor reprocessing until the data-flow state reaches a fixed point.

Rust · compiler backend · register allocation · SysV x86-64

x86-64 Codegen & Register Allocation Lab · Rust

An experimental backend for a restricted IR: SSA/CFG, liveness, register allocation, spills and phi lowering. Register assignments are checked independently; native results are compared against a reference IR interpreter.

Full case study ↗ Source code ↗

Problem

The goal is to go from IR to executable x86-64 and verify that register allocation preserves semantics.

Approach

SSA-like IR with CFG/SSA validation, liveness/interference, register allocation with an independent assignment verifier, phi lowering, and SysV x86-64 code generation.

Outcome & limits

A reference interpreter and differential execution check generated-code semantics; the allocator assignment contract is verified independently.
