UniversalToolchain

Независимо развиваемые language contributions должны собираться в один compiler/runtime pipeline без скрытой зависимости от registration order и без второго resolver в runtime.

GitHub
01

Проблема

Независимо развиваемые language contributions должны собираться в один compiler/runtime pipeline без скрытой зависимости от registration order и без второго resolver в runtime.

02

Ограничения

Независимые версии пакетов, разные backend-ы, детерминизм и обратная совместимость.

03

Решение

Typed artifact contracts; dependencies/conflicts и capability/provider resolution; deterministic pass ordering и artifact routes компилируются в immutable LanguagePlan до исполнения.

04

Результат

LanguageRuntime проверяет exact planned package/component graph и создаёт выбранные компоненты без повторного планирования; контракт защищён determinism/exact-binding checks, ownership guards и interpreter/CIL parity.

05

Как проверялось

Канонический тестовый gate, clean-consumer проекты, parity интерпретатора/CIL, детерминированные манифесты и воспроизводимые падения.

06

Моя ответственность

Архитектура, ключевые контракты, runtime, SSA, тестовая стратегия и публичная документация.
